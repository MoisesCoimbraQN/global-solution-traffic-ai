🎯 FLUXO DE DADOS

1. Coleta (TomTom API)
   └─→ coletor_transito_db.py
   
2. Processamento
   └─→ Cálculo de métricas (velocidade, score de congestionamento)
   
3. Armazenamento
   └─→ PostgreSQL (AWS EC2)
   
4. Análise
   └─→ SQL Queries / Views
   
5. Visualização
   └─→ Dashboards em Tempo Real

📊 TABELAS DO DATA WAREHOUSE

DIMENSÕES:
  • dim_regiao           - Informações geográficas (bairro, zona, cidade)
  • dim_via              - Dados das vias monitoradas
  • dim_tempo            - Dimensão temporal (15 minutos)
  • dim_cruzamento       - Localização dos semáforos

FATOS:
  • fato_transito_tempo_real    - Métricas de tráfego
  • fato_ciclo_semaforo         - Histórico de ajustes

AUXILIARES:
  • horarios_pico        - Configuração de horários de pico

VIEWS:
  • vw_transito_resumido       - Resumo agregado de tráfego
  • vw_eficacia_semaforos      - Análise de eficácia dos semáforos

═════════════════════════════════════════════════════════════════

🚀 COMO COMEÇAR

1. Ativar ambiente virtual:
   .\.venv\Scripts\Activate.ps1

2. Configurar .env com credenciais:
   - DB_HOST, DB_USER, DB_PASSWORD
   - TOMTOM_API_KEY

3. Criar banco de dados:
   python setup_warehouse.py

4. Iniciar coleta de dados:
   python coletor_transito_db.py

🎓 MODELO SNOWFLAKE

O modelo Snowflake é ideal para Data Warehouses porque:

✓ Normalização reduz redundância
✓ Dimensões ramificadas permitem análises flexíveis
✓ Fatos centralizados para métricas
✓ Escalável para novos bairros/cidades
✓ Otimizado para consultas OLAP

Estrutura:
                  [dim_regiao] 
                       │
                       ▼
[dim_tempo] ───> [dim_via] <─── [dim_cruzamento]
                       │
                       ▼
            [fato_transito_tempo_real]
